# 확장 탭 카탈로그 재구성 설계

날짜: 2026-09-06. 상태: 검토 대기.

## 목적

확장 탭을 "설치된 콘텐츠의 카탈로그"로 재구성한다. 워크플로우는 워크플로우로,
기능 확장은 기능으로 분류해 탐색하게 한다. 칸반·깃허브 도구 같은 기능과
TDD 사이클 같은 워크플로우가 한 목록에 섞여 있는 현재 UI의 분류 문제를 푼다.

## 결정된 사항 (사용자 확인)

1. 접근: 카탈로그 골격 + 통일된 패키지 모델. 패키지 형식(v1 pack, v2 extension
   package)을 종류별로 강제 분리하지 않는다 — "켜면 화면·예약·스킬이 함께
   따라온다"는 번들 개념과 기존 팩 두 개(si, starter)를 지키기 위함.
2. 범위: 확장 탭 UI 재구성 + 기존 설치 경로(local/git/https) 유지. 원격
   레지스트리 탐색은 이번 턴 제외.
3. 워크플로우 카테고리: 발행된 네이티브 워크플로우 전부를 함께 표시해 채운다
   (샘플 패키지를 새로 만들지 않는다). 출처가 섞이는 것은 사용자가 수용.
4. 커넥터(github, rss): 소스 탭 확장 관리 화면에 그대로 둔다. 카탈로그는
   `전체 · 기능 · 워크플로우` 세 카테고리만.
5. 탭 라벨은 "확장" 유지.

## 분류 규칙 — 매니페스트 변경 없음, 기여에서 유도

분류는 설치 시점에 사용자가 고르는 값이 아니라 기여(contributions)에서 유도한다.
스키마·백엔드 무변경이고, 복합 패키지가 자연스럽게 여러 카테고리에 걸친다.

- **기능**: v1 팩 전부 + `views/actions/skills/exporters` 중 하나라도 기여하는
  v2 확장 패키지.
- **워크플로우**: `contributions.workflows`가 비어 있지 않은 v2 확장 패키지 +
  `workflow_catalog`의 발행 워크플로우 전부(네이티브).
- **전체**: 위 둘의 합집합. 어느 카테고리에도 걸리지 않는 패키지(예:
  `schemas/analyzers`만 기여)도 전체에는 표시된다.
- **커넥터**: 이번 턴 카테고리 자체를 만들지 않는다.

필요한 데이터는 프론트에 이미 노출돼 있다: `api.listPacks()`(PackRegistryView),
`api.listExtensionPackages()`(manifest.contributions 포함),
`workflowApi.catalog()`(`features/workbench/api`). 신규 invoke 명령 없음.

## 프론트엔드 — `src/pages/PacksPage.tsx` 재구성

- 헤더 아래 카테고리 탭: `전체 · 기능 · 워크플로우`. 상태는 로컬 useState,
  store 무변경.
- **기능 카테고리**: 기존 2단(좌 리스트 + 우 상세) 유지. 설정 편집·스킬 설치·
  액션 실행 기능을 잃지 않기 위함. 좌 리스트가 탭 필터를 따르고 각 항목에
  주입 배지(`화면 2 · 액션 3 · 스킬 5`)를 표시한다.
- **워크플로우 카테고리**: 카드 그리드.
  - 네이티브 워크플로우 카드: 이름·버전·단계 수, "스튜디오에서 열기"로
    `workflows` 페이지로 이동.
  - 확장 주입형(미래): 출처 패키지 명시, 클릭 시 해당 패키지 상세로.
- `통합 확장 패키지` 설치 카드(소스 종류·위치·커밋 입력): 현위치 유지.
- `PageHeader` 설명을 카탈로그 개념으로 갱신
  (예: "이 앱이 할 수 있는 일과 일하는 방식을 여기서 얻습니다").

## 이번 턴 변경 없음

- 백엔드(`src-tauri/`), 매니페스트 스키마, 워크플로 탭·스튜디오, 소스 탭,
  zustand store, `PageId`.

## 검증

1. `tsc --noEmit`.
2. 데스크톱 앱(tauri dev, HMR)에서 카테고리 탭 전환·기능 상세 동작을 사용자가
   직접 확인.
3. 브라우저 preview 모드(`?preview=1`) 스크린샷으로 워크플로우 카드 렌더 확인.

## 비목표 / 향후

- 원격 레지스트리 탐색·원클릭 설치, 레지스트리 스키마·서명 검증.
- 커넥터 카테고리(소스 탭과의 통합).
- 워크플로 탭에서 팩 주입 워크플로우의 출처 배지.
- 워크플로우 전용 패키지 콘텐츠 제작(TDD 사이클 등을 확장 패키지로 추출).
- 기능 카테고리도 카드 그리드로 개편 — 별도 의사결정 후.
