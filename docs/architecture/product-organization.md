# 작업 중심 앱 구조

2026-09-07 UI/UX 정리. 기존 프로젝트·작업·볼트·예약 데이터는 유지하며, 화면의 역할과 진입점을 다음처럼 정리한다.

| 진입점 | 역할 | 하위 화면 |
| --- | --- | --- |
| 작업대 | 현황을 모아 보는 위젯 대시보드 | 위젯 추가, 이동, 크기 조절 |
| 작업 | 일을 정의하고 실행 방법을 관리 | 작업 보드, 오늘 할 일, 실행할 작업, 예약과 반복 |
| 캘린더 | 기한과 일정 | 작업 기한, 약속·마일스톤 |
| 프로젝트 | 프로젝트와 문서 관리 | 프로젝트 카드에서 자료 가져오기·문서 만들기 |
| 이슈 | 이슈 설계·승인·실행 | 마일스톤별 이슈 구성과 진행률 |
| 실행 | 에이전트와 실행 결과 | 터미널, 작업 실행, 협업 세션, 실행 기록, 검토 |
| 볼트 | 볼트의 문서 열람·유형별 보기·상태 점검 | 모든 문서, 일지, 개념, 점검 |
| 확장 기능 | 설치된 기능을 사용 | 읽을거리, 설치된 GitHub |
| 확장 관리 | 기능·스킬·워크플로 설치와 관리 | 설치됨, 마켓플레이스, 스킬, 워크플로 |
| 설정 | 앱 환경과 볼트 구조 | 일반·실행 설정, 볼트 문서 구조 |

프로젝트·설정에는 전역 하위 탭을 두지 않는다. 프로젝트를 고른 상태에서 문서 만들기를 열고, 설정에서 볼트 문서 구조를 연다. 확장 관리는 서로 다른 대상을 한 화면에 섞지 않고 `설치됨 / 마켓플레이스 / 스킬 / 워크플로` 탭으로 나눈다. 작업의 보기 전환과 실행 도구의 전환은 같은 업무 범위이므로 유지한다. 화면 헤더에는 기능명과 조작만 두며 브랜드 문구·감성 제목·반복적인 소개 문단을 표시하지 않는다.

전체 검색과 알림센터는 앱 상단에 항상 있다. 전체 검색은 볼트 문서, 작업, 프로젝트, 실행할 작업 정의, 실행 기록을 함께 찾는다. 알림은 실행 종료·실패, 놓친 예약, 승인 요청, 에이전트 입력 대기·검토, 확장 로드 오류를 모으며 읽음 상태를 저장한다.

## 작업과 예약

기존 `TaskDef`의 실행 내용과 선택적인 `schedule`을 사용한다. 수동·한 번·매일·평일은 서로 다른 작업 종류가 아니라 같은 작업의 실행 방식이다. 활성 팩이 선언한 모든 액션과 호스트의 `인박스 승격 검토`도 같은 “실행할 작업” 목록에 표시한다. 파라미터가 있는 팩 작업은 목록에서 입력값을 받은 뒤 실행한다. 예약 화면에서는 이 중 예약된 작업과 사용자가 예약할 수 있는 작업을 다루며 제목과 프롬프트를 복제하지 않는다. 작업 보드의 프로젝트 진행 항목(`WorkItem`)과 실행 프롬프트 정의(`TaskDef`)는 기존 저장 형식을 유지한다.

앱 시작 시 예약 실행기를 연결한다. 예약 없는 작업도 저장된 정의에서 즉시 실행할 수 있다. 내장 작업 행은 실제 활성 확장의 예약 엔트리에서 만들며, 토글과 시간 수정은 해당 엔트리의 키에 적용한다. 실행 시간의 기준은 데스크톱의 로컬 시간이다.

## 대시보드 복구

`6184877`의 `DashboardBoard`, `layout-store`, `registry`를 현재 `app/`에 복구했다. `react-grid-layout`으로 이동·리사이즈하며 넓은·중간·좁은 화면의 배치를 각각 저장한다. 레이아웃 v1/v2와 최근 `sawhorse.overview-slots` 표시 설정을 v3으로 읽는다. 사용자가 모든 위젯을 숨긴 상태도 유지한다.

작업·캘린더·이슈·실행·예약·읽을거리에서 제공하는 위젯을 카탈로그에 등록한다. 외부 확장이 임의의 JavaScript 위젯을 실행하는 API는 추가하지 않았다.

## 문서 명칭

`노트`를 문서와 별도의 제품 개념으로 노출하지 않는다. 마크다운 파일은 모두 `문서`이며, `일지`와 `개념`은 볼트 문서의 유형별 보기다. 사이드바는 상위 `볼트` 카테고리 아래에 `모든 문서`·`일지`·`개념`·`점검`을 묶는다. `모든 문서`는 전체 파일 트리, `일지`와 `개념`은 해당 문서 목록, `점검`은 볼트 검사와 미승격 항목을 담당한다. 기존 `기록/`과 `노트/` 작업공간은 읽기 호환성을 유지하고, 새 작업공간은 `일지/`와 `문서/`를 사용한다.

## 확장과 연결

읽을거리(`core-feeds`)는 켜고 끌 수 있는 코어 확장이다. GitHub는 `plugin/connector-extensions/github/extension.json`에 별도 manifest로 둔다. 확장 관리에서 설치하면 사용자 확장 디렉터리에 manifest를 배치하고 사이드바 `확장 기능` 아래에 GitHub 페이지를 표시한다. 기존 연결 데이터는 비활성화해도 보존한다. 비활성화한 연결의 동기화 명령은 백엔드에서도 거절한다.

RSS 소스 화면에는 RSS 연결만, 이슈 연동 화면에는 GitHub 연결·가져오기·원격 변경 검토만 표시한다. 연결 권한과 원격 쓰기 승인 경로는 기존 브로커를 사용한다. GitHub 전용 관리 화면은 브라우저 OAuth 승인을 시작하고 발급된 자격 증명만 OS 키체인에 저장한다. 설치 여부와 사용 여부는 별개이며, 사용을 중지해도 설치된 확장과 관리 진입점은 남는다.

관리 화면은 계정이 접근할 수 있는 저장소를 50개씩 불러온다. 검색은 현재 불러온 목록에 적용되며 더 보기로 이어서 읽는다. 저장소의 immutable ID와 계정은 이슈 연결 시 자동 입력된다. 프로젝트로 가져오기는 선택한 로컬 폴더에 Git clone을 수행하고 프로젝트를 등록한다. 계정 연결은 GitHub OAuth Device Flow를 사용하며 Client Secret이나 PAT를 UI에서 받지 않는다. 발급된 OAuth 토큰과 선택적인 refresh token은 OS 키체인에 하나의 자격 증명으로 저장한다. 토큰은 Git의 프로세스 환경에서만 전달하고 저장소 설정이나 URL에 넣지 않는다. 같은 이름의 기존 폴더는 대체하지 않으며, 3분 내 완료되지 않으면 프로세스를 종료하고 이 작업이 만든 임시 폴더를 정리한다. 가져온 프로젝트에서 코드베이스를 입력으로 문서 초안을 만들 수 있다.

GitHub 저장소 목록 계약: [GitHub REST 문서](https://docs.github.com/en/rest/repos/repos#list-repositories-for-the-authenticated-user).

## 마일스톤과 이슈

마일스톤의 이름과 기한은 기존 `calendar/*.md` 일정에 저장하며, 구성 이슈는 기존 이슈 문서의 `milestone` 필드가 정본이다. 이슈 화면과 캘린더가 같은 구성 편집기를 사용한다. 마일스톤 관리는 이슈 화면의 사이드바 한 곳에만 노출하고, 팩이 별도 마일스톤 문서 화면을 사이드바에 추가하지 않는다. 이슈를 다른 마일스톤에 넣으면 해당 필드를 바꾸므로 중복 소속되지 않는다. 완료 진행률은 구성 이슈의 `state: closed` 비율이다. 기존 볼트의 마일스톤 참조도 별도 그룹으로 유지한다.

마일스톤에 이슈가 남아 있는 동안 일정 삭제나 일반 일정으로의 변경을 거절한다. 볼트 진단도 캘린더 마일스톤을 유효한 참조로 인정한다. 여러 이슈 변경은 각 파일을 원자적으로 저장하며, 중간 실패 시 오류를 표시하고 현재 상태를 다시 읽는다. 볼트 전체를 대상으로 한 다중 파일 트랜잭션은 아니다.

## 편집 경험

워크플로는 드래그 가능한 단계 캔버스와 시작 단계·조건·다음 단계를 선택하는 연결 폼으로 편집한다. 단계의 위치는 초안 ID별로 로컬 저장한다. 문서 구조 설정은 입력 형식을 텍스트·숫자·정수·예/아니요·선택 목록으로 고르며 기존 복잡한 정의는 고급 JSON에서 편집한다.

실제 PC의 파일·폴더 경로 입력은 공통 `PathInput`과 Tauri Dialog를 사용한다. 볼트, 프로젝트, 실행 파일, 확장 패키지, 가져올 자료, GitHub 문서·저장소 경로에 적용한다. 볼트 내부의 상대 경로 패턴은 운영체제의 실제 경로가 아니므로 텍스트로 편집한다.

## 마켓플레이스 형식

사용자가 지정한 HTTPS JSON 카탈로그를 읽는다. 기존 다른 서비스의 임의 마켓플레이스 형식을 자동 변환하는 기능은 아니다. 카탈로그 선택은 설치 소스만 채우며 패키지 검증·설치와 프로젝트 권한 적용은 기존 경로를 사용한다. 스킬은 확장 패키지의 `contributions.skills`를 통해 배포한다.

```json
{
  "name": "팀 확장",
  "packages": [
    {
      "id": "team-skills",
      "name": "팀 스킬",
      "category": "skill",
      "description": "팀에서 사용하는 에이전트 스킬",
      "source": {
        "kind": "https",
        "location": "https://example.com/packages/team-skills.json"
      }
    }
  ]
}
```

Git 소스는 HTTPS 저장소 주소와 정확한 40자리 `commit`을 함께 지정한다. 카탈로그는 2MB로 제한하고 중복 ID·로컬 소스·고정되지 않은 Git 소스를 거절한다.

## 검증 범위

Playwright는 명시적인 `?preview=1` 데이터로 위젯 이동·리사이즈·설정 유지, 기존 작업의 반복 예약, 확장 설치에 따른 화면 기여, RSS/GitHub 분리, 시각 편집과 기존 작업·문서 흐름을 검증한다. Rust 테스트는 실제 manifest, 카탈로그 검증, 예약과 실행 경로, 저장소 이름 검증, 마일스톤 참조 무결성과 YAML 필드 보존을 검증한다. 협업 인박스 테스트는 사용자 경로 대신 테스트별 임시 경로를 사용한다.

실계정 GitHub 인증·저장소 복제·동기화와 운영체제 파일 선택창의 클릭·선택은 데스크톱에서 별도 확인이 필요하다. 브라우저 체험에서는 실제 계정·파일·에이전트를 연결하지 않는다.
