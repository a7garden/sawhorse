# 내부 스킬의 하위 모델 선택

부모는 프로젝트/실행에서 고른 모델로 전체 맥락과 통합 책임을 유지한다. SDD·TDD 스킬은 분할 이득이 있는 하위 작업의 난이도와 근거를 판단하고, Herdr 하네스는 그 판단을 검증해 모델 인자로 전달한다. 별도 분류 API 호출이나 사용자별 난이도 선택 단계는 없다.

## 결정과 실행

1. 하네스가 `delegate` 스킬과 현재 정책·동시 실행 한도를 프롬프트에 포함한다. 플러그인 설치 여부에 관계없이 적용된다.
2. 부모 스킬이 범위·불확실성·검증 난이도를 보고 `modelAssessment: {complexity, reason}`을 작성한다. 단순 작업이라도 위임 비용이 더 크면 직접 처리한다.
3. 기존 child inbox에 `model: ""`로 제출한다. 호스트가 모델을 결정하고 `runs/<id>.md`에 `model`, `modelSelection`, `childModelPolicy`를 저장한 다음 Herdr를 시작한다.
4. 시작과 재개 모두 저장된 `model`을 CLI의 `--model`로 전달한다. 설정 변경이나 앱 재시작으로 기존 실행의 모델이 다시 계산되지 않는다.
5. 부모는 자식의 `runs/<id>.evidence.md`와 실행 상태를 읽고 검사한 결과를 정식 워크플로우 산출물에 반영한다.

| 조건 | 결과 |
|---|---|
| 명시한 `model` | 해당 값 우선 |
| 새 루트 실행 | 요청한 부모 모델/CLI 기본값 유지, 현재 정책 저장 |
| auto + Claude + routine/standard | Sonnet |
| auto + Claude + complex | Opus; 부모가 고정한 Opus 버전이면 그 버전 유지 |
| inherit 또는 평가 없는 기존 요청 | 같은 에이전트의 부모 모델 상속 |
| Codex 또는 사용자 정의 공급자 모델 | 같은 에이전트의 부모 모델 상속 |
| 다른 에이전트로 변경하면서 상속 | 다른 제품의 모델 문자열을 넘기지 않고 대상 CLI 기본값 |

자동 매핑은 빈 기본값, Claude의 알려진 family/alias에 적용한다. 사용자 정의 모델 ID를 Sonnet으로 추측해서 대체하지 않는다. `sonnet`과 `opus`는 Claude Code가 해석하는 [공식 모델 별칭](https://code.claude.com/docs/en/model-config)이다. 계정별 이용 가능 여부와 실제 버전은 CLI/공급자가 결정하며, 선택 기록은 실행 요청의 근거이지 사용량 계측이나 비용 절감률이 아니다.

## 역할과 한도

- research/verifier는 어느 작업 노드에서도 보조 조사·검증을 할 수 있고 소스·테스트·정식 산출물을 수정하지 않는다.
- implementer는 implementer 부모와 구현을 허용한 노드에서만 생성한다. 호스트는 실행 트리 내 활성 하위 구현자를 하나로 제한한다. 스킬은 파일 범위를 지정하고 자식 종료 전 부모의 코드 편집을 멈춘다. 파일 쓰기 제한은 에이전트 계약이며 OS 샌드박스 격리는 아니다.
- 깊이는 기존처럼 2단계, 루트당 누적 하위 실행은 8개다. 검증 실패에 따른 상위 모델 재시도도 이 한도에 포함된다. 스킬은 같은 하위 작업을 최대 한 번만 complex로 재시도하고, 인증·모델 이용 불가·쿼터·승인·환경 오류는 재스폰하지 않는다.
- 기존 동시 실행 한도를 지킨다. 새 설치 기본값은 부모+자식이 가능한 2다. 명시적으로 저장된 1은 유지하며, 스킬이 직접 처리하고 설정에서 제한 이유를 안내한다. 한도 초과 inbox는 거절하며 재제출 반복을 하지 않는다.
- requestId 재사용은 이미 저장된 실행을 반환한다. 기존 기록에 정책이 없으면 inherit으로 읽는다. 새 루트만 현재 설정을 받아 같은 트리에 고정한다.

## UI와 검증

설정 → 실행에 `자동 · 스킬이 판단` / `부모 모델 상속`을 제공한다. 실행 상세에는 실제 요청 모델, 자동/명시/상속 출처, 난이도·근거, 자식 정책이 표시된다. 사용자가 작업마다 난이도를 고를 필요는 없다.

Rust 테스트는 모델 결정의 우선순위·공급자 경계, 실제 하위 실행 장부의 Sonnet 저장과 정책 고정·멱등성·역할 제한·기존 기록 호환성을 검증한다. 브라우저 검증은 정책 저장과 실행 모델 근거 표시를 확인한다. 실제 유료 모델의 응답 품질과 토큰 절감량은 별도의 실사용 계측 대상이다.
