# 의도에서 설계·승인·구현·보고까지

Sawhorse의 기본 입력은 사람이 남기는 의도다. 완성된 명세를 요구하지 않는다.
메모와 이미지는 `intent.md`에 저장하고, AI가 이를 해석해 `spec.md`와 `plan.md`를 만든다.
사람이 범위·수용 기준·작업 단위를 검토하고 승인하면 AI가 구현·검증한 뒤
`verification.md`에 변경 사항, 작업 단위별 결과, 실제 검증 명령과 결과, 남은 문제를 보고한다.
사람의 결과 확인이 작업 완료를 결정한다. 에이전트의 idle 신호는 검토 대기일 뿐이다.

## 사람과 AI의 책임

| 단계 | 책임 | 기록 |
| --- | --- | --- |
| 의도 | 사람이 원하는 결과와 제약을 표현 | `intent.md`, 첨부 이미지 |
| 설계 | AI가 요구사항·성공 기준·가정과 질문을 정리하고 작업을 분해 | `spec.md`, `plan.md` |
| 승인 | 사람이 현재 문서를 읽고 구현 범위를 승인 | `work.md` 결정, `approved-design.json` |
| 구현·보고 | AI가 승인된 범위를 구현하고 검증 근거를 보고 | `verification.md`, `runs/` 실행·출력 기록 |
| 결과 인수 | 사람이 실제 결과와 근거를 확인 | `work.md` 완료 결정 |

새 의도는 `intent-flow@1.0.0`을 사용한다. 프로젝트의 기존 SDD·TDD 워크플로 설정으로
이 승인 경계를 바꾸지 않는다. 기존 작업은 시작 당시의 워크플로를 계속 사용한다.
프로젝트의 기본 에이전트와 모델은 의도 실행에 적용한다.

## 문서 이력

현재 문서는 계속 읽고 편집할 수 있으며 다음 시점에 별도 사본을 남긴다.

- 의도 최초 저장
- 앱에서 문서를 수정하기 직전
- 설계를 검토해 구현 승인을 요청한 시점
- 최상위 의도 실행을 접수한 시점
- 구현 결과를 인수하는 시점

각 사본은 `work/<id>/history/<checkpoint-id>/`에 네 문서와 `record.json`을 저장한다.
디렉터리 전체를 작성한 뒤 확정하므로 중간 파일은 이력 목록에 노출되지 않는다.
원래 문서의 상대 이미지 경로는 기존 `attachments/`를 기준으로 해석하며 이미지 파일은 보존한다.
사본은 검토 당시의 근거다. 실제 승인·완료 여부의 정본은 `work.md`와 워크플로 장부다.
검토 사본 저장 후 결정이 실패해도 그 사본 자체를 승인으로 취급하지 않는다.
이전 기록을 보고 있을 때는 실행·승인·완료 버튼을 비활성화하고 현재 문서로 돌아가는 동선을 제공한다.

외부 편집기의 모든 중간 저장을 수집하는 버전 관리 시스템은 아니다. AI가 기존 문서를
다시 작성하기 전의 실행 입력, 사람이 검토한 설계, 인수한 결과를 보존한다.
기능 적용 전의 과거 버전은 현재 파일에서 추정하거나 재구성하지 않는다.

## 실패와 재개

메모 저장과 실행 접수는 구분한다. 실행 장부 작성이 거절되면 의도는 접수 상태를 유지한다.
접수 후 프로세스 시작에 실패하면 실행 기록에 원인과 상태가 남으며 작업 상세에서 확인한다.
설계 승인은 구현 실행 실패로 취소되지 않는다. 승인한 설계가 그대로라면 구현을 재시도한다.
의도·설계·계획이 승인 이후 바뀌면 재검토 전까지 구현 실행과 결과 인수를 차단한다.

응답 대기·중지·실패한 실행은 작업 상세와 연결한다. 알림과 상세의 실행 열기는
프로젝트와 실행 ID를 함께 전달해 해당 실행을 선택한다. 전달하지 않은 피드백은
승인·완료를 차단하며, 화면을 닫기 전 미저장 확인 대상에 포함한다.

## 검증

`tests/intent.spec.ts`는 메모·이미지 보존, 실패 후 접수 상태, 검토 사본 열람,
피드백 처리, 결과 인수, 정확한 실행 이동을 브라우저 체험에서 검증한다.
`sdlc::tests`는 실제 임시 파일에서 원본·검토·결과 사본, 승인 후 변경 차단,
실행 접수 기록과 경로 검사를 검증한다. 브라우저 체험은 실제 AI 실행 성공을 흉내 내지 않는다.
