# 설치 후 자동 작업공간 업그레이드

새 앱의 첫 실행에서 설정된 `vaultPath`와 Sawhorse 설치본을 자동으로 갱신한다. 설치 프로그램이 사용자 파일을 만지는 방식이 아니라, 앱이 자신의 번들·이전 데이터·설치 기록을 확인한 뒤 수행한다. 별도의 마이그레이션 명령은 필요 없다.

## 실행 순서

1. 번들 내용 해시, 업그레이드 규칙 버전, 볼트 경로로 실행 ID를 만든다. 이미 완료된 실행은 다시 적용하지 않는다.
2. 설치된 번들 확장 패키지를 검증하고 새 payload를 준비한다. 기존 프로젝트의 잠금이 있지만 로컬 저장소 사본이 없으면 번들에서 복구한다.
3. 볼트 전체를 별도 사본으로 복사한다. 사본에서 코어 스키마를 초기화하고 레거시 문서를 변환한 뒤 참조·워크플로우·상태를 검증한다.
4. 검증을 통과하면 원본을 백업 경로로 옮기고 사본을 원래 볼트 경로에 배치한다. 복사 이후 원본 내용이 바뀌었다면 교체하지 않는다.
5. Sawhorse 플러그인과 팩·에이전트 스킬을 새 번들로 교체하고 폐지된 스킬과 자동화 호출을 정리한다.
6. 완료 결과, 이관한 작업 수, 확인할 항목과 백업 경로를 보여 준다. 실패하면 앱 작업과 예약 실행을 막고 재시도 화면을 표시한다.

단계별 교체 기록을 저장하므로 프로세스가 중간에 종료되어도 다음 실행에서 이어간다. 전체 작업을 한 번에 롤백하는 트랜잭션은 아니다. 이미 교체한 설치본은 유지하고 남은 단계부터 복구한다. 복구 재시도 성공 후에는 앱을 재시작해 파일 감시와 실행 서비스를 새 경로에 연결한다.

## 데이터별 처리

| 이전 데이터 | 새 버전 처리 |
|---|---|
| `improve.projects`, `coreProjects`의 저장소 경로·검증 명령 | 코어 프로젝트에 보완한다. 기존 코어 값은 우선한다. |
| `프로젝트/` 또는 `사업/` 아래 이슈·개선 노트 | `work/<id>/work.md`와 요청·설계·결과 산출물로 변환한다. |
| 상태·우선순위·담당자·레이블·GitHub 연결 | 코어 작업의 해당 필드로 옮긴다. |
| 프로젝트 간 중복 ID | 경로에 기반한 안정적인 새 ID를 배정하고 의존 관계를 연결한다. 같은 프로젝트 안의 모호한 ID 중복은 중단한다. |
| 이슈 의존 관계 | ID와 위키링크의 실제 대상 문서를 새 작업 ID로 연결한다. 이미 이관한 문서도 조회하며 링크 별칭은 식별자로 쓰지 않는다. 모든 작업을 만든 뒤 관계를 기록해 파일 순서에 영향을 받지 않는다. |
| 마일스톤 | `calendar/`의 프로젝트 마일스톤으로 옮기고 작업 참조를 연결한다. 마감일이 없거나 비어 있으면 일정 미정으로 보존한다. 입력된 날짜는 유효해야 한다. 일정 미정 항목은 캘린더 목록에서 날짜 없이 조회·편집할 수 있다. |
| 원문·알 수 없는 필드 | 원래 문서와 `work/<id>/legacy-source.md`에 남긴다. 원래 문서에는 `migrated_to`만 추가한다. |
| 이미지·일지·지식 문서·커스텀 문서 스키마 | 폴더 구조와 내용을 보존한다. 추출한 산출물의 일반 Markdown 인라인 상대 링크는 원래 위치를 가리키도록 보정한다. |
| 기존 코어 작업·workflow/schema 공개 버전 | 그대로 보존한다. 공개된 정의를 덮어쓰지 않는다. 이해할 수 없는 코어 형식은 중단한다. |
| 오래된 기본 템플릿·Base·대시보드 | 이전 볼트 백업에 보존하고 활성 볼트는 새 기본 자산을 사용한다. |

## 플러그인과 자동화

- Claude 설치 기록의 Sawhorse 항목과 개인 skills 폴더의 Sawhorse 플러그인을 교체한다. 기존 설치 기록의 scope와 다른 플러그인 항목은 유지한다.
- Codex의 Sawhorse 프롬프트를 재생성한다. 같은 이름의 다른 개인 프롬프트는 덮어쓰지 않고 충돌을 알린다.
- 이전 개인 `improve`, `improve-excel` 등은 Sawhorse 소유 표시가 있는 경우에만 비활성화한다. 이전 트리는 백업에 남는다.
- 기존 `si`, `starter` 오버라이드는 백업 후 기능 확장(`journal`, `concepts`, `todos`, `project-docs`)으로 이행하고, 설치된 번들 확장의 어댑터·스킬을 갱신한다. 다른 사용자 팩과 타사 플러그인은 보존한다.
- 확장 패키지의 이전 immutable payload는 과거 작업의 고정 참조를 위해 유지한다. 더 최신인 활성 버전은 낮추지 않는다. 새 권한이 필요한 프로젝트 잠금은 이전 버전을 유지하고 결과 화면에서 활성화 방법을 안내한다.
- 활성 자동화의 `/sawhorse:improve` 호출을 `/sawhorse:issues`로 바꾼다. 이전 엑셀 자동화는 일시 중지하고 XLSX Export 활성화 및 새 액션 선택을 안내한다. 저장된 프롬프트와 자동화 이력은 보존한다.

## 백업과 복구

실행 기록은 `~/.claude/sawhorse/upgrades/<실행 ID>/report.json`에 저장한다. 홈 안의 교체 대상은 같은 실행 폴더의 `backups/`에, 외부 볼트는 원래 볼트 옆의 `.이름.sawhorse-backup-<ID>`에 백업한다. 자동으로 백업을 삭제하지 않는다.

날짜 오류·없는 의존 대상·이관 표시와 실제 데이터의 불일치·심볼릭 링크·경로 충돌·복사 중 변경·디스크 오류는 실패 사유가 된다. 문제가 있는 원본을 수정한 뒤 재시도할 수 있다. 백업이 이미 존재하는 교체 중간 단계에서는 원본 자리에 임의로 새 폴더를 만들지 않는다.

실제 사용자 볼트에 적용하는 실행은 앱 시작 시에만 일어난다. 개발 중 `tauri dev` 역시 같은 시작 경로를 사용한다. 검증은 실제 홈을 읽지 않는 임시 홈·볼트 fixture와 브라우저의 모의 native bridge로 수행한다. 대용량 볼트는 전체 사본과 보존 백업을 위한 여유 공간이 필요하다. 심볼릭 링크를 포함한 볼트와 미지원 형식은 자동으로 추측해 바꾸지 않는다.
