# vault-tidy — 볼트 재구성/다듬기

기존 문서 전체를 훑어 si-workbench 표준 구조(`일지/`, `사업/<사업명>/`, `개념/`, `첨부/`, `템플릿/`)로 재구성하고, **매 실행 볼트를 올바른 상태로 되돌려 놓는다.**

두 가지 책임이 있다:

1. **상시 정규화** — 루트에 쌓인 붙여넣기 이미지 회수, 첨부 폴더 설정 교정, frontmatter 스키마 정합, 죽은 링크 정리. 실행할 때마다 무조건, 승인 없이 수행한다.
2. **재구성** — 노트 이동·병합·보강·삭제. 계획을 세워 승인받은 뒤에만 수행한다.

첫 실행은 전체 패스, 이후 실행은 git diff 기반 증분 패스. 재실행 멱등을 지향한다.

## 안전 규칙 (최우선)

- git은 **로컬 버저닝 전용**. remote 추가·push·원격 동기화는 절대 하지 않는다.
- 첫 재구성 전 반드시 현재 상태를 git 커밋으로 박제한다(원본 보존 — 모든 변경은 히스토리에서 복구 가능해야 한다).
- **삭제·병합·본문 보강·파일명 변경은 계획 승인 후에만** 실행한다. 승인 없는 파괴적 변경 금지.
- 반대로 [NORMALIZE]에 열거된 조치(폴더 배치, 설정 교정, 빈 키 추가, 명백한 링크 오타)는 내용을 바꾸지 않고 되돌릴 수 있으므로 승인 없이 매번 수행한다. 이 목록은 스킬이 임의로 늘리지 않는다.
- frontmatter는 템플릿 스키마만 사용한다. 임의 필드 금지. 키는 영어, 값은 한국어.
- 위키 규범은 si-workbench:wiki를 준수한다.
- vault 경로 결정: `${user_config.vault_path}` → `%USERPROFILE%\.claude\si-workbench\config.json`의 `vaultPath` → 사용자에게 절대경로 문의. 순서대로 시도한다.

## 0. git 기반 마련

1. `<vault>/.git`이 없으면 `git init`한다. repo 로컬 범위로 `user.name`/`user.email`이 비어 있으면 `si-workbench` / `si-workbench@local`로 설정한다.
2. 전체를 스테이징해 초기 커밋: `vault-tidy: 원본 백업 (마이그레이션 전 상태)`.
3. `.gitignore` 작성(없으면): `.obsidian/workspace.json`, `.obsidian/workspace-mobile.json`, `.trash/`
4. 이미 git이 있으면: 미커밋 변경 목록을 보고하고, 사용자 동의를 얻어 커밋하거나 그대로 둔다(어느 쪽도 자동으로 덮지 않는다).

## 상시 정규화 (매 실행 무조건, 승인 불필요)

[NORMALIZE] 스캔 범위가 증분이든 전체든, `$ARGUMENTS`가 무엇이든 **매 실행 이 절을 먼저 수행한다.** 볼트를 항상 올바른 상태로 되돌려 놓는 것이 이 스킬의 상시 책임이다. 여기 적힌 조치는 되돌릴 수 있고 내용을 바꾸지 않으므로 승인 없이 실행하되, 무엇을 했는지 전부 보고한다. 삭제·병합·본문 보강은 여기 포함되지 않으며 기존 승인 게이트를 따른다.

**실행 방법** — 아래 1~8을 노트를 하나씩 열어가며 확인하지 않는다. 스크립트 한 번으로 목록을 받고, 판단이 필요한 것만 손으로 처리한다:

```
powershell -NoProfile -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/scripts/vault-hygiene.ps1" -VaultPath "<vault>" -Mode fix
```

`fix`는 1·2·5·7(기계적 이동·설정·`.base` 보정·H1 제거)을 직접 수행하고, 3·4·6·8·9(고아 첨부·스키마 이탈·수집 대기·죽은 링크·파생 표)와 루트 미분류 노트는 목록으로만 낸다. 그 목록을 아래 규칙대로 처리하는 것이 스킬의 몫이다.

**일과 루틴과의 분담** — 매 실행 전부 훑으면 느리므로 하루 세 번에 나눠 돈다. vault-tidy는 전체를 한 번에 도는 수동 패스이고, 평소에는 이 분담이 볼트를 정상 상태로 유지한다:

| 모드 | 담당 | 성격 |
|---|---|---|
| `quick` | morning | 즉시형 위생 — 첨부 회수, 설정 교정, 자산·미분류 확인 |
| `scan` | lunch | 진단 전용 — 죽은 링크·고아 첨부·스키마 이탈 (읽기 전용) |
| `fix` | evening | 위 둘 전부 + 판단이 필요한 정리 |
| `fix` | vault-tidy | 위 전부 + 재구성(이동·병합·보강·삭제) 승인 게이트 |

스크립트 실행이 실패하면(PowerShell 없음 등) 중단하지 말고 사유를 보고한 뒤, 1~8을 직접 수행하거나 건너뛴 항목을 명시한다.


1. **표준 폴더 밖 첨부 파일 회수** — vault 루트와 표준 폴더(`일지/`, `사업/`, `개념/`, `첨부/`, `템플릿/`) 밖에 흩어진 비 md 파일(`.png .jpg .jpeg .gif .webp .svg .pdf .xlsx .docx .hwp .hwpx .zip` 등)을 찾는다. 붙여넣기로 생긴 `Pasted image *.png`가 대표 사례다.
   - 이미지·스크린샷 → `첨부/스크린샷/`, 그 외 문서·자료 → `첨부/`로 옮긴다. 사업이 명확히 특정되는 다이어그램은 `첨부/다이어그램/<사업명>/`.
   - 파일명은 바꾸지 않는다. 위키링크는 파일명으로 해석되므로 폴더만 옮기면 `![[파일명.png]]`가 그대로 살아 있다.
   - 대상 폴더에 같은 이름이 이미 있으면 **옮기지 않고** 충돌로 보고한다.
   - 옮긴 뒤 해당 파일을 참조하는 노트에서 임베드가 여전히 해석되는지 확인한다. 상대경로(`![](./x.png)`)로 참조하는 곳이 있으면 경로를 고친다.
2. **재발 방지 설정** — `<vault>/.obsidian/app.json`의 `attachmentFolderPath`가 비어 있거나 루트(`/`, `.`)면 `첨부/스크린샷`으로 설정한다. 이미 다른 폴더로 지정돼 있으면 사용자의 선택이므로 건드리지 않고 보고만 한다. (이 설정이 없으면 붙여넣기 이미지가 계속 루트에 쌓인다 — 1번의 근본 원인이다.)
3. **고아 첨부 탐지** — `첨부/` 아래 파일 중 어떤 md에서도 참조되지 않는 것을 목록으로 보고한다. **삭제하지 않는다.** 삭제는 승인 게이트 대상이다.
4. **frontmatter 스키마 정합** — 각 노트의 `type`에 해당하는 `템플릿/<유형>.md`와 대조한다.
   - 템플릿에 있는데 노트에 없는 키를 **빈 값으로** 추가하고, 키 순서를 템플릿 순서로 맞춘다.
   - **기존 값은 절대 바꾸지 않는다.** 값 채우기는 보강이며 승인 대상이다.
   - 템플릿에 없는 키가 있으면 지우지 말고 보고한다(사용자가 의도적으로 넣었을 수 있다).
   - `type: 대시보드`(볼트 루트 `대시보드.md`)와 `.base` 파일은 템플릿 대조 대상이 아니다. 존재 여부만 5번에서 확인한다.
5. **인덱스 자산 확인** — `대시보드.md`(볼트 루트), `개념/개념.base`, `사업/사업.base`, `사업/개선.base`, `일지/일지.base`가 있는지 확인한다. 없으면 `/si-workbench:init-vault` 실행을 안내한다(여기서 만들지 않는다). 있으면 각 `.base`의 YAML이 파싱되는지, 참조하는 프로퍼티가 실제 노트에 존재하는지 확인하고 어긋난 것을 보고한다. 또한 `type`으로 거르는 `.base`가 `템플릿/` 폴더를 제외하고 있는지 확인한다 — 빠져 있으면 `not: [file.inFolder("템플릿")]`을 최상위 `filters`에 추가한다(템플릿 노트가 목록에 섞이는 것을 막는 안전 조치이므로 승인 없이 고친다). 이미 `file.inFolder(...)`로 범위를 좁힌 `.base`(개선의 사업 범위)는 템플릿이 섞일 수 없으므로 그대로 둔다.
   개선 폴더(`사업/<사업명>/개선/`)에는 사업 범위 `.base`(`<idPrefix> 개선.base`)가 하나 있어야 한다. 스크립트가 `[개선base]`로 없는 것을 알려주면 **여기서 만들지 말고** `/si-workbench:improve` 실행을 안내한다(그 스킬이 자기 asset에서 만든다).
   개선 폴더는 **평면**이다 — 화면단위 하위 폴더(`개선/fdrList.do/`)가 남아 있으면 옛 구조이므로 `[개선폴더]`로 보고하고, 문제 노트를 `개선/` 바로 아래로 올릴지 사용자에게 제안한다(화면 구분은 노트의 `url` 프로퍼티가 한다). 위키링크는 이름으로 풀리므로 이동으로 깨지지 않는다.
6. **개념 수집 승격** — 노트 어디에든 있는 `## 개념 수집` 섹션에서 아직 `[[링크]]`가 붙지 않은 줄을 찾는다. si-workbench:wiki 의 "수집 메모 승격" 절차로 개념 노트를 만들고 원본 줄의 용어만 링크로 감싼다. 문맥 문장은 그대로 둔다. 뜻을 확정하지 못한 것은 `status: 확인필요`로 남기고 보고에 모은다.
7. **파일명과 겹치는 H1 제거** — Obsidian은 에디터 최상단에 파일명을 인라인 제목으로 이미 보여주므로, 본문 첫 줄의 `# 파일명`은 제목이 화면에 두 번 나오게 한다(위키 규범 제7조). 파일명과 **같은** H1만 지운다. `내부망_외부망_Apache_구조.md` → `# 내부망/외부망 Apache 통신 구조`처럼 파일명이 담지 못한 정보가 들어 있는 H1은 그대로 둔다. 템플릿(`템플릿/`)은 이미 H1이 없어야 하며, 남아 있으면 템플릿에서도 지운다.
8. **죽은 링크 스캔** — 전체 md의 `[[...]]` 대상이 노트나 alias로 존재하는지 확인한다. 대소문자·공백만 다른 명백한 오타는 고치고, 대상이 아예 없는 링크는 개념 노트 생성 대상으로 보고한다(자동 생성은 위키 규범 절차를 따른다).
9. **파생 표 탐지** — 스크립트의 `[파생표]`는 개선 문서(`개선.md`, `* 문제목록.md`)가 문제 노트 프로퍼티를 마크다운 표로 베껴 둔 것이다. 상태가 두 곳에 있으면 **반드시 어긋나므로**(위키 규범 제6조) `.base` 뷰 임베드로 바꿔야 한다.
   - 본문을 다시 쓰는 일이라 [NORMALIZE] 자동 조치가 아니다. 3번 「계획 수립 → 승인」에 올려 승인받은 뒤 바꾼다.
   - 바꿀 때 **프로퍼티에서 나오지 않는 열은 살린다** — 목업 파일 링크, 파일 겹침 판정, 구현 순서 제약, 확인 결과 서술. 이것들은 표에서 떼어 별도 절로 옮긴다. 상태·커밋·승인 열만 버린다.
   - 필요한 `.base`가 없으면 `/si-workbench:improve` 가 만들게 한다.

10. **보고** — 위 1~9에서 실제로 한 일과 못 한 일(충돌·판단 보류)을 표로 남긴다. 아무것도 할 게 없었으면 "정규화: 이상 없음"이라고 명시한다.

## 1. 스캔 범위 결정

- HEAD가 있고 `$ARGUMENTS`에 `full`이 없으면(증분): `git diff --name-status HEAD`의 변경 파일 + untracked만 대상. 대상이 없으면 "마지막 정리 이후 변경 없음"을 보고하고 종료한다.
- 첫 실행이거나 `full`이면: vault 전체 `*.md`(제외: `.obsidian/`, `.git/`, `.trash/`, `템플릿/`).
- 위 판정과 무관하게 [NORMALIZE]는 이미 수행된 상태다. 증분 대상이 없어도 정규화 결과는 보고한다.

## 2. 분류·진단

노트마다 기록: 현재 경로, 추정 유형, 상태 태그.

- 추정 유형: 일지(파일명이 날짜), 사업·연구(사업명 추정 가능), 회의(회의록 형태 — 사업 귀속이 추정되면 `사업/<사업명>/회의/`, 아니면 기타와 동일 처리), 개념(용어 정의 형태), 기타(미분류)
- 상태 태그:
  - `빈 노트` — 제목만 있거나 본문이 실효성 없음(1-2줄). 단 `type: 개념`이면서 `status`가 `확인필요`/`초안`인 노트는 **의도적으로 수집된 스텁**이므로 빈 노트로 분류하지 않는다(삭제 후보에 올리지 않는다).
  - `부실 노트` — 있으나 최소 설명이 없음(대략 5줄 미만)
  - `파편 후보` — 같은 주제의 짧은 노트가 2개 이상
  - `스키마 누락` — frontmatter 없음 또는 키 불일치
  - `위치 불량` — 표준 폴더 밖
- 노트 본문은 스캔을 위해 읽되, 대용량 노트는 앞부분 요약만으로 판단한다.

## 3. 계획 수립 → 승인 (하드 게이트)

아래 표를 사용자에게 제시하고 **승인을 받기 전까지 어떤 쓰기도 하지 않는다**:

| 조치 | 대상 | 내용 |
|---|---|---|
| 이동 | 원래 경로 → 새 경로 | 표준 폴더 배치 + frontmatter 작성 |
| 병합 | 파편 목록 → 남을 노트 | 본문 통합. 사라지는 이름은 남을 노트 `aliases`에 등록(기존 `[[옛이름]]` 링크가 alias로 해석됨) |
| 보강 | 부실 노트 | 관련 소스(제안서·코드·기존 노트·세션 기록)가 있을 때만 무엇으로 채울지 제안. **추측 서술 금지** |
| 삭제 | 빈 노트 | 사용자 승인 필수 (git 이력에 남음) |

애매한 판단(사업명 귀속, 병합 대상 선정, 유형)은 이 단계에서 질문으로 해소한다.

## 4. 실행

- **이동**: 폴더 배치 + frontmatter 채우기(스키마 순서 고정) + 파일명과 겹치는 H1 제거(제7조). 일지로 분류된 노트는 파일명을 `YYYY-MM-DD.md`로 정규화한다(같은 날짜 노트가 이미 있으면 병합 후보로 승인 단계에 올린다). 상대경로 링크·임베드(`![[...]]` 제외한 상대 경로)가 깨지지 않는지 확인한다.
- **병합**: 남을 노트에 본문을 통합하고 `aliases`에 사라지는 이름들을 추가한다. 중복 문장은 제거한다.
- **보강**: 승인된 항목만, 근거 소스를 `sources`에 남기며 채운다.
- **삭제**: 승인된 항목만.
- **위키링크 정비**: 새로 등장한 개념은 규범대로 노트를 만들고, 관련 사업 허브의 `## 문서`·`## 주요 개념` MOC를 갱신한다.

## 5. 검증·마무리

1. 죽은 링크 스캔: [NORMALIZE] 8번을 재구성 결과에 대해 한 번 더 수행한다(이동·병합으로 링크가 새로 깨졌을 수 있다).
2. 커밋: `git add -A` → `vault-tidy: 정규화 P·이동 N·병합 M·보강 K·삭제 D·링크수정 L` 형식.
3. 보고: [NORMALIZE] 표 + 조치별 건수와 목록, 죽은 링크 처리 결과, 고아 첨부 목록(삭제하지 않았음을 명시), 다음 실행은 증분으로만 동작하지만 정규화는 매번 돈다는 안내.
