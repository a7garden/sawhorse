# evening — 퇴근 정산

무인 실행 스킬이다. daily-log와 daily-report의 절차를 조합해 한 번에 처리한다. 퇴근 루틴은 이 스킬 하나로 끝난다.

## 무인 실행 계약

[UNATTENDED] 사용자는 자리를 비운 상태에서 이 스킬을 실행한다. 어떤 단계에서도 사용자에게 질문하거나 응답을 기다리지 않는다. 모든 판단과 근거는 마지막 보고에 적는다. 사용자 확인이 필요한 사항은 실행을 멈추지 말고 보고서에 "확인 필요"로 표시한다.

## 공통 원칙

- 코드베이스는 읽기 전용으로만 다룬다. 어떤 저장소의 파일도 수정/삭제하지 않는다.
- **사용자가 쓴 글은 지우지 않는다.** 일지 노트의 어떤 섹션에서든 사람이 손으로 적은 문장을 삭제하거나 요약문으로 대체하지 않는다. 무인 실행이라도 예외 없다. 계약은 4단계 [PRESERVE].
- 원격 저장소 변경 주의: `git push`, `svn commit`/`svn ci`, `git svn dcommit`, `hg push`는 불필요하면 실행하지 않는다. 로컬 `git commit`은 자유이며, 훅(block-push.ps1)이 원격 변경은 실행 전 사용자 확인을 요구한다.
- 위키 규범은 si-workbench:wiki를 준수한다. 업무기록 본문에서 개념이 처음 등장하면 `[[개념명]]`으로 링크하고, 개념 노트가 없으면 템플릿(`템플릿/개념.md`) 내용으로 생성한다. 죽은 링크 금지.
- 프로퍼티 키는 영어, 값은 한국어. 스킬이 임의 필드를 만들지 않는다.
- vault 경로 결정: `${user_config.vault_path}` → `%USERPROFILE%\.claude\si-workbench\config.json`의 `vaultPath` → 사용자 문의. 무인 실행이므로 어디서도 경로를 못 찾으면 질문하지 말고 실패 사유를 보고하고 종료한다.

## 절차

1. **오늘 일지 노트 확보** — `${vault}/일지/YYYY-MM-DD.md`(로컬 날짜). 노트가 없으면 템플릿(`템플릿/일지.md`) 내용으로 생성한다.
2. **저널 분석** — daily-log의 분석 절차를 그대로 수행한다: 오늘 저널(`%USERPROFILE%\.claude\si-workbench\journal\<오늘>.jsonl`) 로드 → session_id dedup → [SAMPLING] → cwd 기준 프로젝트별·시간순 재구성. `$ARGUMENTS`(세션에 남지 않은 구두 업무)가 있으면 분석 결과에 반영한다. 저널이 없고 `$ARGUMENTS`도 없으면 기록 근거 없음을 보고에 적고 3단계로 간다.

[SAMPLING] transcript JSONL 샘플링 규칙: (1) 전체 통독 금지. (2) 먼저 라인 수 파악. (3) `"type":"summary"` 라인과 user 발화(`message.role == "user"`이고 content가 문자열이거나 content[].type=="text")를 추출. (4) 마지막 assistant 텍스트 1-2개만 추가. (5) tool_result 본문은 읽지 않는다. 파일이 크면 앞부분 user 발화와 뒷부분 마무리를 우선.

3. **체크 확정 (증거 기반)** — `## 오늘 할 일`의 각 항목을 2단계 분석 결과와 대조한다. 판정 기준은 lunch 4단계의 대조 규칙과 동일하다(항목 문구와 작업 내용이 명백히 일치할 때만 근거 인정, 애매하면 미완료 유지). 완료의 명백한 근거가 있으면 `- [x]`로 바꾸고 근거(세션/프로젝트)를 보고에 적는다. 사용자가 이미 [x]한 항목은 유지한다. 근거가 없으면 [ ]를 유지하고 보고에 "증거 없음"으로 표시한다. 이 단계에서 `## 오늘 할 일`에 가하는 변경은 체크 상태(`[ ]`↔`[x]`)뿐이다. 항목 문구를 고치거나 삭제하지 않는다.
4. **업무기록 기입** — daily-log와 동일한 계약으로 `## 업무기록`을 갱신한다. `## 업무기록` 헤딩이 없으면 문서 끝에 헤딩과 자동 영역 마커를 함께 추가한다:

[PRESERVE] **사용자가 쓴 문장은 어떤 경우에도 사라지지 않는다.** (1) 쓰기 전에 `## 업무기록` 전체와 `## 비고`·`## 내일 할 일`을 읽는다. (2) 노트 수정 전 원본을 `%USERPROFILE%\.claude\si-workbench\backup\일지-<YYYY-MM-DD>-<HHmmss>.md`로 복사한다(폴더 없으면 생성, 실패 시 수정하지 말고 보고). (3) `<!-- si-workbench:auto:start -->`~`<!-- si-workbench:auto:end -->` 사이만 교체 가능한 자동 영역이다. 마커가 하나라도 없으면 섹션 전체를 사용자 수기 기록으로 간주하고 마커를 새로 만든다. (4) 마커 밖 수기 기록은 덩어리(문단) 단위로 재가공한다 — 오늘 한 일은 자동 영역의 해당 블록에 통합, "~할 것/~필요"는 `## 내일 할 일`에 `- [ ]`로 추가, 개념·시스템 구조 설명은 개념 노트로 옮기고 `[[링크]]`와 한 줄 요약만 남김, 사업/개선 상세는 해당 노트로 옮기고 링크만 남김, 그 외 메모(연락처·IP·경로·잡기)는 `## 비고` 끝에 덧붙임, **분류가 애매하면 옮기지 말고 자동 영역 바깥에 원문 그대로 보존**한다. 원문의 수치·고유명사·사람 이름·주소·사용자 판단은 표현을 바꾸지 않는다. (5) 원문 제거는 완전히 동일한 문장이 대상 섹션에 이미 있을 때만 허용하며, 요약·의역으로 원문을 대체하지 않는다. (6) `## 비고`·`## 내일 할 일`은 덧붙이기만 한다(기존 줄 삭제·수정 금지). (7) 재가공한 덩어리마다 `원문 첫 문장(20자) → 옮긴 위치`를 종합 보고에 표로 남긴다. 옮긴 위치가 없는 원문이 하나라도 있으면 잘못된 것이다.

자동 영역 기록 규칙: 시간순 프로젝트/작업 블록, 각 항목에 무엇을·왜·결과, 한국어 완결 문장, 개념 첫 등장 시 `[[개념명]]` 위키링크(노트 없으면 템플릿 생성).

5. **보고서 출력** — daily-report의 [REPORT-FORMAT]을 그대로 따른다: 단일 코드블록, `[분류]` + `- 항목`, 분류 사이 빈 줄, 날짜/인사/장식 없음. AI가 그날 분류를 추론한다. 출력 직전 4점 자가점검: 코드블록 1개인가, `[분류]` 형식인가, 빈 줄 구분인가, 장식 없는가.
6. **내일 할 일 정리** — 3단계 후에도 `- [ ]`인 항목을 `## 내일 할 일`에 이어 적는다. 기존 항목은 삭제하지 않고, 완전히 동일한 문구는 중복 추가하지 않는다. `## 내일 할 일`이 초기 상태(주석과 빈 `- [ ]`)면 미체크 항목으로 채운다.
7. **볼트 위생 (fix)** — 아래 [HYGIENE] 계약대로 `fix` 모드를 실행하고, 스크립트가 판단을 미룬 항목까지 처리한다. 하루 중 유일하게 판단이 필요한 정리를 수행하는 지점이다. 무인 실행이므로 애매하면 고치지 말고 보고에 "확인 필요"로 남긴다.

[HYGIENE] 볼트 위생 점검. 한 번에 전부 훑으면 느리므로 morning/lunch/evening 이 모드를 나눠 맡는다. 점검은 스킬이 노트를 하나씩 읽지 않고 아래 스크립트 한 번으로 목록만 받아 처리한다.

```
powershell -NoProfile -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/scripts/vault-hygiene.ps1" -VaultPath "<vault>" -Mode <quick|scan|fix>
```

| 모드 | 담당 | 스크립트가 하는 일 | 쓰기 |
|---|---|---|---|
| `quick` | morning | 표준 폴더 밖 첨부 회수, `attachmentFolderPath` 교정, 루트 미분류 노트 탐지, 인덱스 자산 확인(볼트 공통 + 개선 범위별 `.base`), `.base` 템플릿 폴더 제외 보정, 개선 문서의 파생 표 탐지, 파일명과 겹치는 H1 제거 | 기계적 이동·설정만 |
| `scan` | lunch | 죽은 링크·고아 첨부·frontmatter 스키마 이탈·중복 H1 진단 | 없음 (읽기 전용) |
| `fix` | evening | quick + scan 전부 | 기계적 조치 |

스크립트는 판단하지 않는다. 아래는 출력 목록을 받아 **스킬이** 처리한다:

- `[수집]` — 사용자가 `## 개념 수집` 섹션에 문맥과 함께 적어둔 용어다. si-workbench:wiki 의 "수집 메모 승격" 절차로 개념 노트를 만들고, **원본 줄의 용어만 `[[링크]]`로 감싼다**(문맥 문장은 그대로 둔다). 문맥 없이 일반 상식으로 정의를 쓰지 않는다 — 동음이의어가 섞여 있다.
- `[미분류]` 루트 노트 — 성격을 보고 올바른 폴더로 옮긴다. 용어를 모아둔 메모면 같은 승격 절차를 쓴다. 판단이 서지 않으면 옮기지 말고 보고한다. 원본 노트는 사용자가 지우라고 하기 전까지 삭제하지 않는다.
- `[스키마]` frontmatter 없음/키 누락 — 누락 키를 **빈 값으로만** 추가하고 순서를 템플릿에 맞춘다. 값은 채우지 않는다(값 채우기는 vault-tidy 승인 대상).
- `[죽은링크]` — 대소문자·공백만 다른 명백한 오타는 고치고, 대상 자체가 없으면 개념 노트 생성 대상으로 보고한다.
- `[제목중복]` — 파일명과 같은 H1 이다. `quick`/`fix` 가 이미 지웠으므로 보고만 확인한다. `scan` 이 잡아낸 것은 다음 `quick`/`fix` 가 처리한다. 스킬이 직접 손댈 일은 없다.
- `[고아첨부]` — **삭제하지 않는다.** 목록만 보고한다.
- `[개선base]` — 개선 폴더에 사업·화면 범위 `.base` 가 없다. 여기서 만들지 말고 `/si-workbench:improve` 실행을 안내한다(그 스킬이 asset 에서 만든다).
- `[파생표]` — 개선 문서가 문제 노트 프로퍼티를 마크다운 표로 베껴 두고 있다. **반드시 어긋나므로** `.base` 뷰 임베드로 바꿔야 한다. 본문을 다시 쓰는 일이라 여기서 자동으로 고치지 않고, 목록과 함께 `/si-workbench:improve` 또는 `/si-workbench:vault-tidy` 를 안내한다.
- `[충돌]` `[경고]` — 그대로 보고한다.

스크립트 실행에 실패하면(PowerShell 없음, 경로 오류 등) 루틴을 멈추지 말고 "볼트 위생: 실패 — <사유>" 한 줄만 남기고 나머지 절차를 계속한다.

8. **종합 보고** — 아래 순서로 마무리한다:

```
실행 요약:
- 저널 N세션(M프로젝트) 분석, 업무기록 교체, 보고서 출력

체크 확정:
- [x] 항목 — 근거
- [ ] 항목 — 증거 없음 (직접 확인 필요)

내일 이월:
- (6단계에서 옮긴 항목)

수기 기록 이관:
- 원문 첫 문장 → 옮긴 위치 (수기 기록이 없었으면 "수기 기록 없음")

백업:
- (원본 노트 복사 경로)

볼트 위생:
- 이동/교정: (한 줄)
- 승격: (수집 메모에서 개념 노트로 올린 용어. 없으면 "없음")
- 처리함: (미분류 노트 배치, 스키마 키 보정, 링크 오타 수정)
- 확인 필요: (고아 첨부 목록, 판단 보류한 항목)
```

## 금지

- `## 오늘 할 일`에서 근거 없이 항목을 [x]로 바꾸지 않는다.
- `## 비고`·`## 내일 할 일`의 기존 줄을 수정·삭제하지 않는다([PRESERVE] 이관을 위한 덧붙이기만 허용).
- `## 업무기록`의 수기 기록을 읽지 않고 덮어쓰지 않는다. 백업 없이 노트를 수정하지 않는다.
- 보고서 코드블록 외의 장식(인사, 이모지, 요약 박스)을 추가하지 않는다.
- 보고서 코드블록과 종합 보고에 `[[위키링크]]` 표기를 쓰지 않는다(터미널 출력이므로 일반 문구로 풀어쓴다). 단 `## 업무기록` 본문은 위키 내용물이므로 링크를 유지한다.
