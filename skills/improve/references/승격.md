# 승격 (문제목록 → 문제 노트)

`improve` 스킬의 0-A 단계 상세. **SKILL.md 의 안전 규칙·폴더 구조·금지사항이 전제다.**
`<idPrefix> 문제목록.md` 에 승격되지 않은 항목이 있을 때만 읽는다.

사용자는 목록 파일 하나에 여러 문제를 편하게 적는다. 스킬은 각 항목을 문제 노트로 분리한다.

## 승격 대상 판정

아래 둘 다 훑는다. 어느 쪽도 없으면 승격할 것이 없는 것이다.

1. `## 신규 (미승격)` 섹션의 내용 — 스킬이 정비한 뒤의 표준 입력 자리
2. **레거시 포맷** — 문서가 아직 표준 구조로 정비되지 않은 경우. 다음 규칙으로 읽는다:
   - `## <번호>` 또는 `## <임의 제목>` 헤딩 하나 = 문제 1건. `## 목록` / `## 신규 (미승격)` 헤딩은 제외한다.
   - 항목 첫머리의 2열 표(`| 화면 | ... |` 형태)에서 `화면`/`URL`→`url`, `구분`→`category`, `중요도`→`priority`, `상태`→`status` 를 읽는다. 없는 행은 비워 둔다.
   - 옛 문서의 `화면 ID`(`UI_LDM_FAB-…`)·`화면명` 행은 **프로퍼티로 옮기지 않는다.** 스키마에 그 필드가 없다. 화면 안의 위치를 짚는 값이면 `## 문제상황` 첫머리에 문장으로 남기고, 아니면 버린다.
   - `### 문제상황` → `## 문제상황`, `### 원인 분석` → `## 원인 분석`, `### 해결 방안` / `### 개선 방안` → `## 원인 분석` 끝의 `### 사용자 제안`, `### 해결 결과` → 내용이 있으면 `## 결과` 로 옮기고 비어 있으면 버린다.
   - 제목은 `## <번호>` 처럼 내용이 없으면 `## 문제상황` 첫 문장에서 뽑아 짓고, **사용자에게 확인받는다**.
   - `상태` 값이 매핑되지 않으면 `제안` 으로 두고 보고한다.

## 옮기는 방법

- 항목 본문(문제상황·원인 분석·해결 방안 초안)과 이미지 임베드(`![[...png]]`)를 **문제 노트로 이동**한다. 사용자가 적은 문장은 요약·윤색하지 않고 그대로 옮긴다.
- 이미지 파일 자체는 옮기지 않는다. Obsidian 은 `![[파일명]]` 을 볼트 전역에서 이름으로 해석하므로 노트만 이동해도 링크가 유지된다.
- 사용자가 이미 적어둔 해결 방안은 `## 설계` 가 아니라 `## 원인 분석` 끝의 `### 사용자 제안` 으로 옮긴다. 설계는 다음 단계에서 이 제안을 출발점으로 삼아 스킬이 작성한다.
- 승격된 노트는 `status: 제안`, `approve: false`, `priority: 보통` 으로 만든다. ID 는 개선 폴더 전체를 스캔해 최대값 + 1.
- `url` 은 요청 단위 URL 하나(`fdrList.do`)를 적는다. **화면마다 하위 폴더를 만들지 않는다** — 문제 노트는 `개선/` 바로 아래 평면으로 둔다.
- 사용자가 적은 내용에 「대외 산출물이 틀리게 나간다」·「업무가 막힌다」가 드러나면 `priority` 를 올리고 **왜 올렸는지 보고에 적는다.** 근거 없이 올리지 않는다.
- 목록 문서는 **base 뷰 임베드 + 신규 작성 영역** 구조로 재작성한다. 목록을 마크다운 표로 다시 쓰지 않는다 — 상태는 문제 노트가 정본이고 두 곳에 두면 반드시 어긋난다:

  ```markdown
  <사업 한 줄 설명>. 상태의 정본은 각 문제 노트이고, 아래 표는 그 프로퍼티에서 만들어진 뷰다 — 손으로 고치지 않는다.

  ## 화면별 목록

  ![[<idPrefix> 개선.base#화면별]]

  ## 신규 (미승격)
  <!-- 새 문제를 자유롭게 적으세요. 다음 실행 때 문제 노트로 승격됩니다.
       화면(url)·구분·중요도를 2열 표로 적어두면 그대로 옮겨집니다. -->

  ## 승격 이력
  <!-- 원본 항목 → 만들어진 문제 노트. 프로퍼티에 없는 기록이라 여기 남는다. -->
  ```

  `<idPrefix> 개선.base` 가 없으면 SKILL.md 「인덱스 자산」대로 asset 에서 만든다.

- 원본 목록 문서를 덮어쓰기 전에 승격 대상과 이동될 내용을 보여주고 **확인을 받는다.** 확인 전에는 쓰지 않는다.
- 볼트 루트 등에 있는 기존 `개선 제안/` 같은 임시 폴더, 또는 옛 구조의 화면단위 하위 폴더(`개선/fdrList.do/`)를 발견하면 표준 위치(`사업/<사업명>/개선/` 평면)로 옮길지 제안한다. 이동은 사용자 확인 후에만 한다. 위키링크는 이름으로 풀리므로 이동으로 깨지지 않는다.
- 끝나면 SKILL.md 의 「전파」에 따라 `개선.md` MOC 를 갱신하고 스캔으로 돌아간다.
